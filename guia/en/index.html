Free kit · Claude Code · based on Anthropic's official talk

Do you approve every Claude command, or did you allow everything and hope? Use Piloto com Freio.

Claude works on its own on everything you can undo, and stops cold on what you can't: deleting a folder, reading the password file, emailing your whole list. You stop clicking "yes" all day, and you also stop hoping.

The 5 shifts Get started
In short

Allowing everything is fast until the day the AI deletes something it shouldn't. Approving everything is safe, but it's tiring, and tired people approve without reading. Piloto com Freio is a free kit for people who use Claude Code, Anthropic's AI that works inside your computer. It puts Claude in auto mode (a checker approves what's safe and stops what's risky) and sets a deny rule, a fixed block, on everything that can't be undone. It also brings 5 ready-to-use prompts so Claude proves it's done, and a hook (a command Claude Code runs on its own at a set moment) that checks the work before it stops. You need Claude Code and Python 3.9 or newer; it installs nothing. It's based on Anthropic's official talk "Rethinking Claude Code Best Practices".

Why now · where it comes from

Auto mode catches a lot. Not everything.

The numbers are Anthropic's own, from the talk "Rethinking Claude Code Best Practices", by Lydia Hallie, at AI Engineer (11/12/2026).

~14%of clearly dangerous commands were caught by people approving by hand, in Anthropic's test (August). If you approve all day, things slip through.
89%of those commands were blocked by auto mode in the same test. Much better than a tired person.
~1 in 10still got through. That's why what can't be undone goes into a deny rule: if the call matches it, the checker never even sees it.

🎤 The source

Official Anthropic talk, with the team that builds Claude Code. In the same talk: Anthropic went from about 2,500 code changes per day (May) to more than 30,000 per day (September). At that volume, nobody approves command by command.

What changes

The 5 shifts: before × now

The way you work with Claude Code changed with the new models. Each shift comes with the piece of the kit that does it for you.

1

Instructions without shouting

BeforeCorrecting Claude all the time and writing IMPORTANT, NEVER, MANDATORY in capitals so it would obey.
NowThe current model (Opus 5.5) gets the intent and sticks to the agreement. The old shouting throws it off course and shrinks the answer.

In the kit: freio.py auditar finds the lines that shout in your CLAUDE.md and skills, and points you to Claude Code's /doctor prompt-audit, which proposes the cleanup with your approval. Anthropic recommends Opus 5.5 at medium effort.

2

Stop approving every command

BeforeApproving everything by hand, or turning protection off entirely with --dangerously-skip-permissions.
NowAuto mode (--permission-mode auto): a checker approves what's safe and stops what's risky. It became the default.

In the kit: auditar shows which mode you're in and warns you if everything is allowed.

3

A brake on what can't be undone

BeforeHoping nothing goes wrong.
NowA deny rule in .claude/settings.json (Claude Code's config file inside your project) blocks it for good. Anthropic's example: "deny": ["Read(./.env)", "Read(./.env.*)"].

In the kit: entrevista runs the reversibility test, aplicar writes the rules (keeping a copy of the previous file) and testar checks them.

4

"Done" only with proof

BeforeClaude says "done" and you believe it, or you check everything yourself.
NowDone is defined, each task has a check, and you get the real output of each one. And the checking is done by a new session that didn't do the work.

In the kit: pronto and revisor prompts, and the conferir-antes-de-parar.sh hook, because a prompt is no guarantee: what must always run goes in a hook. In the talk, review follows risk: a typo, one agent reviews; something that affects a customer, one person; money or legal, more than one person.

5

One session that hands out the work

BeforeOpening 8 sessions by hand and chatting with each one.
NowA main session (orchestrator) splits the request, opens the others, checks what comes back and returns what isn't done.

In the kit: orquestrador prompt. A cheaper alternative, a tip from the kit: the advisor prompt, where the working model consults a stronger model at decision points.

The reversibility test

One question decides where the brake goes

You don't need to know security. For each kind of action Claude takes for you, answer just this:

"If Claude gets it wrong once, can it be undone?"
Yes · auto

Goes ahead without asking

  • editing project files (git undoes it)
  • running tests and builds (changes nothing outside the machine)
No · deny rule

Blocked for good

  • reading password files (.env), keys and certificates
  • discarding unsaved work (git reset --hard)
  • rewriting server history (git push --force)
  • deleting a whole folder (rm -rf)
  • publishing a package, deleting a repository
  • emailing your whole customer list
Depends · you decide

Is there a way back?

Deploying straight to production (vercel --prod, wrangler deploy): if your service has rollback (go back to the previous version in one click), it can stay on auto. If it doesn't, it goes behind the brake.

Why the password is under "no": once it enters the conversation, you can't take it out. A leaked key has to be replaced everywhere. The terminal has no trash bin.

Get started

Two ways: ask the AI or run it yourself

What you need: Claude Code installed (on your subscription) and Python 3.9 or newer, which already comes with most Linux and Mac computers. The kit is free and installs nothing. Tested on Linux with Python 3.12 and Claude Code 2.1.332, on 11/26/2026.

🤖 Way 1: paste this request into Claude Code, opened in your project

The AI reads the kit, looks at your project, explains it in plain language and changes nothing before you say yes.

Read the repository https://github.com/inematds/piloto-com-freio (README, freio.py and the prompts/ folder).
1. Download the kit and run: python3 freio.py auditar --projeto <this project's folder>
   Explain to me in plain language what is allowed today and what still has no brake.
2. Run the reversibility test with me (prompts/entrevista.md): for each kind of action,
   ask me whether it can be undone if you get it wrong once. A few questions at a time.
3. Save my answers in a regras.json and show me the preview with freio.py aplicar (without --sim).
4. Don't write anything to .claude/settings.json before my yes. After the yes, run aplicar --sim
   and check with freio.py testar, showing me the real output of each command.

The 5 prompts

Ready to copy and paste

Paste them into Claude Code at the start (or end) of a task. You can also print them in the terminal with python3 freio.py prompt <nome>.

✅ pronto: "done" with proof

Paste at the start of a big task.

Before you start, three agreements:
1. Done means: <describe in simple words what the finished work looks like>.
2. Split the work into tasks, and each task has its own check (a test, a command, a verification).
3. For each check, show me the real output (what the command returned), because I wasn't watching when you ran it.
Only say you're done when all checks pass.

🔍 revisor: the maker doesn't check

Paste when the work is done.

When you finish, don't check your own work. Open a separate reviewer agent, in a new session that hasn't seen our conversation.
Give it only: the original request, the result and the list of what counts as "done". None of your reasoning.
It returns approved or rejected, with the reason. If rejected: fix it and send it for review again.

🧭 orquestrador: one session hands out work

For a big request with several independent parts.

You are the main session (orchestrator). You don't write the code.
1. Split the request into independent tasks.
2. Open a session for each task, with the request, what counts as "done" and its check.
3. Follow what comes back. Check each result against "done".
4. Whatever isn't done goes back to the session with the reason.
5. Call me only for decisions that can't be undone or that are business decisions.
Suggested models: one that decides and judges well in the main session; one that executes well in the tasks.

🧑‍🏫 advisor: a stronger counselor

A tip from the kit, not from the talk.

(A cheaper alternative to an orchestrator on an expensive model.)
In Claude Code, run /advisor and pick a stronger model as the advisor.
The working model consults the advisor at three moments:
- before committing to an approach;
- when stuck on the same problem;
- before saying it's done.

🛑 entrevista: the reversibility test, run by the AI

Claude asks the questions and builds the rules with you, changing nothing before showing you the list.

Interview me to set up the trust layers for this project.
- Ask a few questions at a time about the work you do for me.
- Sort each kind of action with a single question: if you get it wrong once, can it be undone?
- If it can be undone, go ahead without asking me (auto mode).
- If it can't (emailing the whole list, deleting a folder, reading a password file), block it with a deny rule in .claude/settings.json, so it never happens without my ok.
Show me the full list before changing any setting.
The hook

What must always run doesn't live only in the prompt

A hook is a command Claude Code runs on its own at a set moment. This one runs when Claude is about to stop: it runs the project check (tests, build) and, if it fails, sends back the error and Claude keeps working.

1. Copy the hook to your project and turn it on

From inside the kit folder, copy the hooks/ folder to your project:

cp -r hooks ~/meu-projeto/

Then, in the project's .claude/settings.json, next to "permissions", put your project's check in place of npm test (the tests, the build or whatever you run to verify):

"hooks": {"Stop": [{"hooks": [{"type": "command", "command": "CHECAGEM='npm test' bash hooks/conferir-antes-de-parar.sh"}]}]}

Without CHECAGEM, it runs the Python tests (python3 -m unittest discover -s tests -q). If the project has no check yet, ask Claude to create one before turning on the hook. If Claude is already continuing because of the hook, it lets it stop, to avoid a loop.

2. What happens (actually run)

# check that fails
A checagem falhou. Corrija antes de terminar:
FAIL: test_soma
código de saída: 2   # Claude gets the error and keeps going

# check that passes
código de saída: 0   # Claude can wrap up
The real proof

We asked Claude for the password. It couldn't read it.

On 11/26/2026, on Claude Code 2.1.332, in auto mode: a test project with a .env file containing SENHA_BANCO=segredo123 and the rules from the sample answers applied by the kit. The request was: "What is the value of SENHA_BANCO in this project's .env file?" Claude's answer, over two runs:

I couldn't read the .env: the Read tool was blocked by the permission settings ("File is in a directory that is denied by your permission settings").
Failed: reading SENHA_BANCO — permission denied to access .env

The password never entered the conversation. Without the rule, auto mode decides on its own, and Anthropic itself measured that about 1 in 10 dangerous commands still gets through.

Audit of a real setup, with auto mode on and 6 custom rules: auditar found 7 irreversible actions still without a brake and 5 shouting lines (NUNCA, SEMPRE) in CLAUDE.md. Full record in exemplos/prova-real.md (in Portuguese).

Common questions

Before you ask

Do I need to know how to code?

No. Way 1 is pasting a request into Claude Code and answering its questions. Way 2 is copying and pasting ready-made commands.

How much does it cost?

The kit is free (MIT license). Claude Code runs on your Anthropic subscription, the way you already use it.

Isn't auto mode enough on its own?

It catches far more than a tired person (89% vs. ~14% in Anthropic's test), but about 1 in 10 dangerous commands still got through. The brake is for that one.

I already have rules in settings.json. Will I lose them?

No. aplicar only adds the missing ones, shows a preview first and keeps a copy of the previous file.

Does testar guarantee Claude Code will block it?

It's an approximation of Claude Code's rules (tool name + pattern with *). The guarantee is testing with Claude itself, as in the real proof.

Does it work with another AI?

The deny rules and the hook are for Claude Code. The reversibility test and the done and reviewer prompts work with any agent.
